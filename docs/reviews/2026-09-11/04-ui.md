## 2. `WsProvider.tsx` analysis

**Shape**: 1280 lines, of which ~600 are doc comments. One ref-backed `Store` (`:436-507`), `useSyncExternalStore` selectors with structural sharing (`deepEqual` `:399-430`, `applySnapshot` `:634-712`).

**State held** (`Store`, `:436-507`):
| Slice | Source | Verdict |
|---|---|---|
| `status` (connecting/open/closed) | socket events | keep |
| `hasSnapshot` | first `endpoints` | keep |
| `endpointIds/endpointsById/endpointsArray` | `E.endpoints` mirrored | keep (pure mirror) |
| `firmwareStatus`, `rememberedRobots`, `discoveredServices` | `E` mirrored | keep; would collapse into one `snapshot` slot |
| `logsByEndpoint` + `logOrder` LRU (500 lines × 8 endpoints) | `line` + `error` | keep unless host stores log history in DB |
| `flashProgressByEndpoint` | `flash-progress`/`flash-result`, cleared on snapshot `flashStatus` absent | **delete if** `EndpointListEntry.flashStatus` grows a `source` (host bug, documented `:66-81`) |
| `flashResultHandlers`, `flashLocalReadyHandlers` | pub/sub for one-shot events | keep (events, not state) |
| `wifiCredentials`, `wifiProvisionResultByEndpoint` | `WC`, `WPR` | **delete if** host puts stored network + last provision outcome in the snapshot |
| `telemetryByEndpoint` (header + 600-frame ring + listeners) | `telemetry` | keep (client-side rate decoupling is legitimate) |

**Client-side derivation that the host could own**: almost none. The store does *not* infer connection state from console lines, does not merge endpoints across transports, has no auto-connect, no per-endpoint timers. The only derivations:
- Telemetry frame `t = Date.now()` (`:767`) — host could timestamp.
- Telemetry ring reset on `sessionOpen` true→false (`:672-674`) — host could publish a session generation.
- `flashProgress` cleared when snapshot lacks `flashStatus` (`:705-709`) — workaround for frozen wire type.
- `appendHostError` synthesizes a console line from `type:"error"` (`:626-632`) — presentation choice; fine.

**Reconnect**: `:1024-1036`. Fixed 1.5 s retry on `close`; no backoff; never clears snapshot; relies on host re-sending `endpoints` on connect. Nothing is re-requested by the store on reconnect (ConfigurationPage re-sends `get-wifi-credentials` on `status==="open"`, `ConfigurationPage.tsx:126-131`).

**Message types handled**: 9 inbound (`:949-1015`); `flash-local-ready` and `flash-result` fan out to handlers rather than store.

**> 80-line units**:
- `useEffect` socket lifecycle incl. `connect()` and the 9-way `switch`: `:912-1049` (137 lines).
- Module doc comment `:1-127` (127 lines).
- `applySnapshot` `:634-712` (78 lines; 26 of them parameter comments).

**What a "snapshot + deltas from DB" contract would let you delete**:
- If the host publishes one `snapshot` document (endpoints + firmware + roster + discovery + wifi + per-endpoint flash progress incl. source + last provision result): `firmwareStatus/rememberedRobots/discoveredServices/wifiCredentials/wifiProvisionResultByEndpoint/flashProgressByEndpoint` slices and their 5 selector hooks (`:1112-1173`), the `flash-progress` branch (`:975-981`), the undefined-guards in `applySnapshot` (`:637-659, 689-699`) → roughly 150 lines.
- If the DB is keyed by a stable device id (not link id) and the host publishes `links[]` under each device, `FrontPage.groupEndpointsByRobot/linkScore/bestClassified` (`FrontPage.tsx:258-314`) go away entirely.
- If the host emits a `version`/`revision` per snapshot, `deepEqual` per entry (`:399-430, :665`) can be replaced by a per-row `updatedAt` compare.
- Do **not** delete: the ref-backed store pattern, `useSyncExternalStore` selectors, telemetry ring, log buffer — these are about render isolation at 20 Hz, orthogonal to where truth lives.

## 5. Front page: roster construction and "I turned it on, show it now"

**How the roster is built** (`FrontPage.tsx:160-256`): `useEndpoints()` → `groupEndpointsByRobot` (Map keyed by `name ?? "endpoint:<id>"`, host order preserved for first appearance, members sorted by `linkScore`) → one `RobotCard` per group → `RememberedRobotsSection` for `E.rememberedRobots`. `discoveredServices.robots` is **only** used to populate the relay dropdown (`:166`) — never rendered as a card.

**How a newly-seen robot appears**: only when the host adds an `EndpointListEntry` for it. `applySnapshot` replaces `endpointIds`/`endpointsById` wholesale on every `endpoints` message (`WsProvider.tsx:661-687`) — no merge, no filtering, no debounce. `notify()` fires after every message (`:958`). `useEndpoints` returns `endpointsArray`, rebuilt whenever ids/entries change (`:685-687`). So a new row renders on the next snapshot; there is no UI-side lag.

**Presence display**: purely `sessionOpen`/`sessionError` (`:341-349, 414`). There is no "seen but not linked" vs "gone" distinction beyond the host dropping the row.

**Where "turned on → visible immediately" can fail on the UI side**:
1. **Discovered-but-not-endpoint robots are invisible.** A WiFi robot advertising via mDNS that the host's roster gate hasn't converted to a `wifi-<name>` endpoint has no card (test asserts this: `FrontPage.test.tsx:566-576`). The UI *has* the data (`discoveredServices.robots`) and discards it for the card list. If the new host publishes a device row the moment the watcher sees it, this goes away; otherwise render discovered robots as cards.
2. **Grouping key changes when the name resolves.** A USB board first arrives with `name: null` → group key `endpoint:usb-…`; once SWD naming completes the key becomes the name → React `key` changes (`:239`) → card remounts. Cosmetic flicker; `RelayQuickConnect`'s local `selectedName` state is lost.
3. **Two robots, same name** (host lists a stale relay child with `sessionOpen:false` plus a fresh USB link) fold into one card; the stale link shows "Unreachable" under the card rather than disappearing. Not a UI bug, but the UI has no way to hide a stale link — needs host `lastSeenAt`/`stale` flag.
4. **Nothing on the UI refreshes on reconnect** other than waiting for the host's on-connect snapshot. If the new host does not push `endpoints` immediately on WS open, the front page shows the last-known list forever (`WsProvider.tsx:1028-1031` deliberately keeps it).
5. `deepEqual` structural sharing (`:665`) means a row whose *only* change is not in `EndpointListEntry` (e.g. host-internal `lastSeenAt` not on the wire) will not re-render — correct today, but a new snapshot must include any presence field you want shown.
6. No remounting/stale-closure hazards found in `FrontPage`: no `useEffect` caches the device list; `RelayQuickConnect`'s effect (`:500-504`) only syncs `selectedName` from the child.

Nothing in `FrontPage` filters unknown-classified devices out; `UnknownDevicePage` is reachable for them.
